# Bug audit — 2026-09-06

Branch: `bug-audit-2026-09-06`.

This report records confirmed defects found during a source review of the renderer,
runtime adapters, mod installation and storage, account handling, and host settings.
Each finding lists its trigger, consequence, the fix that was applied, and the
regression test that now covers it. This is a bounded audit of the reviewed flows,
not a claim that the codebase is free of all defects.

Baseline before fixes: 93 frontend tests and 91 quadrant-core tests passing, lint passing with five pre-existing
`react-hooks/exhaustive-deps` warnings.

## Findings and fixes

### Q-01 (High) Mod install page can submit empty or stale values
- **Where**: `src/components/Pages/ModInstallPage/ModInstallPage.tsx`
- **Trigger**: Open a mod's install page when the saved `lastUsedModpack` no longer exists, or before the config values have loaded, and press download. The selects render the first option, but the state still holds `""` or the deleted pack name.
- **Consequence**: The backend receives an empty version or a nonexistent modpack and fails, or installs into the wrong pack.
- **Fix**: Load versions, modpacks, and saved settings together, then reconcile: prefer the saved pack if it still exists, else the applied pack, else the first pack, and derive version and loader from it. Render a fallback option when the version is not in the list. Disable the button until the choices are loaded and while any required value is empty. `Button` gained a `disabled` prop.
- **Tests**: `ModInstallPage.test.tsx` (installs into displayed pack; replaces deleted saved pack; blocks downloads until loaded; concrete default version for resource packs), `Button.test.tsx` (prevents clicks while disabled).

### Q-02 (High) Modpack update skips a changed download with the same file name
- **Where**: `src-tauri/crates/quadrant-core/src/modpacks.rs`, `install_modpack`
- **Trigger**: A synced or shared pack updates a mod to a new version whose download URL ends in the same basename (common with Modrinth `mod.jar` naming).
- **Consequence**: The old bytes stay on disk while the manifest claims the new version.
- **Fix**: Read the old manifest before downloading. Reuse an existing file only when the old manifest records the same id, source, and download URL. Reject manifests with duplicate target file names before any filesystem work.
- **Tests**: `install_modpack_replaces_changed_download_with_same_file_name`, `install_modpack_rejects_duplicate_file_names_before_writing`.

### Q-03 (High) Local mod install accepts an unchecked modpack name
- **Where**: `src-tauri/crates/quadrant-core/src/mc_mod/mod.rs`, `install_local_file`
- **Trigger**: A caller passes `../outside` or an absolute path as the modpack name.
- **Consequence**: The mod file and a rewritten `modConfigV2.json` land outside the modpacks directory.
- **Fix**: Call `validate_modpack_name` (now `pub(crate)`) before any path is built.
- **Tests**: `install_local_file_rejects_modpack_path_traversal_before_writing`, `install_local_file_installs_into_valid_modpack`.

### Q-04 (High) Modpack create/rename trusts a stale listing
- **Where**: `src-tauri/crates/quadrant-core/src/modpacks.rs`, `create_modpack` and `update_modpack`
- **Trigger**: The renderer's modpack list is stale (another window or sync created a pack) and the user creates or renames to that name.
- **Consequence**: `create_dir_all` succeeds on the existing directory and the manifest is overwritten.
- **Fix**: Create the pack directory exclusively with `create_dir` and map `AlreadyExists` to the existing error. Check the rename destination on disk (including symlinks) before mutating the manifest.
- **Tests**: `create_modpack_preserves_existing_manifest_with_stale_snapshot`, `update_modpack_rejects_existing_destination_before_changing_manifest`.

### Q-05 (Medium) Cache index rewritten outside the writer lock
- **Where**: `src-tauri/crates/quadrant-core/src/mc_mod/cache.rs`
- **Trigger**: Two downloads finish while `init_cache` or `get_cache_index` prunes and rewrites `cacheIndex.json`.
- **Consequence**: An entry added between the read and the write is lost, so the file is re-downloaded later or the index references a pruned file.
- **Fix**: All three entry points take `CACHE_WRITE_LOCK`; the prune logic moved into a private `init_cache_locked` that callers invoke while holding the lock.
- **Tests**: `concurrent_cache_maintenance_and_downloads_preserve_every_entry`.

### Q-06 (High) Logout swallows keyring deletion errors
- **Where**: `src-tauri/crates/quadrant-core/src/account/mod.rs`, `clear_account_token`
- **Trigger**: The keyring is locked or unavailable when the user logs out.
- **Consequence**: The UI reports a successful logout while tokens remain in the keyring.
- **Fix**: Attempt every deletion, then return the first error. Both host secret stores already map a missing entry to success, so a fresh install still logs out cleanly.
- **Tests**: `clear_account_token_reports_failures_and_attempts_every_deletion`.

### Q-07 (High) Login without a new refresh token keeps the old account's token
- **Where**: `src-tauri/crates/quadrant-core/src/account/id.rs`, `oauth2_login`
- **Trigger**: Log in as account B after account A when the token endpoint issues no refresh token.
- **Consequence**: B's access token is paired with A's refresh token; the next refresh silently switches back to A.
- **Fix**: Delete `refreshToken` before storing the new access token. The refresh path keeps its token when no replacement is issued.
- **Tests**: `login_without_refresh_token_removes_previous_account_refresh_token`, `refresh_without_replacement_retains_current_account_refresh_token`.

### Q-08 (High) JSON settings store accepts non-object JSON and ignores reload errors
- **Where**: `src-tauri/crates/quadrant-host/src/lib.rs`, `JsonFileStore`
- **Trigger**: The config file is truncated, replaced by an array, or edited externally to an invalid document, then any setting is written.
- **Consequence**: The store treats the file as empty or keeps a stale snapshot, and the next write overwrites the on-disk contents.
- **Fix**: Parse directly into a map so non-object documents are errors, and propagate reload failures so writes stop until the file is repaired.
- **Tests**: `json_store_rejects_non_object_documents`, `json_store_preserves_invalid_disk_contents_on_mutation`.

### Q-09 (Medium) Modpack search is case-sensitive on the query side
- **Where**: `src/tools.ts`, `getModpacks`
- **Trigger**: Type `Fabric` or an uppercase pack name in the modpack search box.
- **Consequence**: No matches, since fields are lowercased but the query is not.
- **Fix**: Normalize the query once before filtering.
- **Tests**: `tools.test.ts` (matches uppercase queries against names and loaders).

### Q-10 (Medium) Browser store change subscriptions are no-ops
- **Where**: `src/desktop/browser.ts`
- **Trigger**: Run the renderer in the browser and change a setting that another component subscribes to.
- **Consequence**: Subscribers never update, so browser dev behaves differently from Tauri.
- **Fix**: Dispatch a window-level custom event on every write, deliver it to subscribers filtered by store and key, return real unsubscribe functions, and reject unserializable values.
- **Tests**: `browser.test.ts` (four cases).

### Q-11 (Medium) Provider deep links accept missing IDs and substring actions
- **Where**: `src/deepLinks.ts`
- **Trigger**: `curseforge://install` with no `addonId`, `modrinth://modpack/...` (matched `mod` by substring), or a Modrinth link with a trailing slash.
- **Consequence**: The app opens an install page for an empty or wrong ID, or rejects a valid link.
- **Fix**: Require a non-empty ID, match the content type by exact segment, and strip a wrapped `https://modrinth.com` prefix.
- **Tests**: `deepLinks.test.ts` additions.

### Q-12 (Medium) "Search further" paginates with the unsubmitted search text
- **Where**: `src/components/Pages/SearchPage/SearchPage.tsx`, `runSearch`
- **Trigger**: Search for `sodium`, edit the box to `sod` without submitting, then press the load-more arrow.
- **Consequence**: Results for a different query are appended under the old ones.
- **Fix**: Store the submitted query in `submittedQueryRef` and use it for appends.
- **Tests**: `SearchPage.test.tsx` (appends results for the submitted query).

### Q-13 (Medium) New search during an in-flight append leaves pagination stuck
- **Where**: `src/components/Pages/SearchPage/SearchPage.tsx`, `searchFurther`
- **Trigger**: Press load-more, then submit a new search before the append resolves.
- **Consequence**: The `sliding` flag was never reset, so the arrow stayed disabled.
- **Fix**: Capture the request id before sliding and only reset state when no newer request has started; block load-more while a fresh search is running.
- **Tests**: `SearchPage.test.tsx` (keeps pagination usable when a new search supersedes an in-flight append).

### Q-14 (Medium) Search results auto-install into a stale saved target
- **Where**: `SearchPage.tsx`, `src/components/shared/Mod.tsx`
- **Trigger**: The pack chosen in the search filters differs from `lastUsedModpack`, or the saved pack was deleted.
- **Consequence**: One-click install went to the wrong pack or an absent one.
- **Fix**: SearchPage passes the resolved target pack as `installTarget`; `Mod` uses it instead of global config, and marks results auto-installable only when a concrete target exists.
- **Tests**: `Mod.test.tsx` (uses explicit target), `SearchPage.test.tsx` (not auto-installable when saved target is gone).

### Q-15 (Low) Failed settings read leaves the download button disabled
- **Where**: `src/components/shared/Mod.tsx`
- **Trigger**: Reading `config.json` throws before the install call.
- **Consequence**: The reads sat outside the `try`, so the in-flight flag was never cleared.
- **Fix**: Move the reads into the `try` block.
- **Tests**: `Mod.test.tsx` (allows retrying after reading settings fails).

### Q-16 (Medium) Current modpack page applies stale refreshes and leaks watchers
- **Where**: `src/components/Pages/CurrentModpackPage/CurrentModpackPage.tsx`
- **Trigger**: Two filesystem watch events fire in quick succession and resolve out of order, or React StrictMode double-mounts the page.
- **Consequence**: The older response wins, and the shared `mountedRef` let the obsolete effect resurrect itself and keep its watcher.
- **Fix**: Per-effect `cancelled` flag and request counter; only the latest response is applied and obsolete watchers are released.
- **Tests**: `CurrentModpackPage.test.tsx` (two cases).

### Q-17 (Medium) Mod install page shows a previously viewed mod's dependencies
- **Where**: `ModInstallPage.tsx`
- **Trigger**: Open mod A, then quickly open mod B while A's owner/dependency requests are pending.
- **Consequence**: A's data overwrote B's, and progress listeners were not removed when the effect re-ran.
- **Fix**: Split the mod-specific effect, guard with a `cancelled` flag, reset lists on change, and unlisten on cleanup.
- **Tests**: `ModInstallPage.test.tsx` (ignores dependencies from a previously viewed mod).

### Q-18 (Medium) Installing an Online-sourced mod panics the command task
- **Where**: `src-tauri/crates/quadrant-core/src/mc_mod/mod.rs`, `install_mod` and `check_mod_updates`
- **Trigger**: The update checker marked every source auto-installable, including `Online`, and the install path hit `unimplemented!()` for that source when the user clicked install.
- **Consequence**: The async command panics, the renderer promise never settles, and the card's in-flight flag stays stuck.
- **Fix**: Return an `unsupportedDownload` error for `Online` and never mark Online mods auto-installable.
- **Tests**: `install_mod_rejects_online_source_without_panicking`, `check_mod_updates_never_marks_online_mods_autoinstallable`.

### Q-19 (Medium) One damaged sync file blanks the whole modpack list
- **Where**: `modpacks.rs`, `get_modpacks`; `src-tauri/src/modpacks/general.rs`
- **Trigger**: A single pack has a malformed `quadrantSync.json`, an unreadable folder, or an unopenable manifest.
- **Consequence**: The loop aborted with `?`, the Tauri command swallowed the error into an empty list, and every operation that lists packs first (delete, rename, install, share) failed with no message. A hostile `last_synced` could also overflow.
- **Fix**: Degrade per entry: skip unreadable folders, treat damaged sync metadata as "never synced", show an unopenable manifest as an unknown pack, and use saturating multiplication. The command now logs the error it swallows.
- **Tests**: `get_modpacks_tolerates_damaged_sync_metadata`.

### Q-20 (Medium) Unknown notification websocket frames force a reconnect loop
- **Where**: `account/id.rs` (`NotificationWsFrame`), `quadrant-host/src/lib.rs` (`handle_notification_ws_frame`)
- **Trigger**: The backend emits any event type the client does not know, such as a heartbeat.
- **Consequence**: Deserialization failed, the socket was dropped, and the host re-bootstrapped history on every reconnect.
- **Fix**: Add a `#[serde(other)] Unknown` variant and ignore it with a debug log.
- **Tests**: `unknown_notification_frames_deserialize_without_error`.

### Q-21 (Medium) Export aborts on subdirectories and leaves a truncated archive
- **Where**: `modpacks.rs`, `export_modpack_to`
- **Trigger**: A staging directory left by an interrupted install sits inside the pack, or the destination cannot be written.
- **Consequence**: `read` on a directory failed the export, and the output file had already been created, so a truncated zip remained at the chosen path.
- **Fix**: Archive regular files only, write to a `.part` sibling, and rename into place on success.
- **Tests**: `export_modpack_skips_directories_and_leaves_no_partial_archive_on_failure`.

### Q-22 (Low) Mods with non-allowlisted download URLs cannot be deleted
- **Where**: `modpacks.rs` `delete_mod`, `mc_mod/mod.rs` `install_remote_file`
- **Trigger**: A legacy or hand-edited manifest entry whose URL fails the current scheme/host policy.
- **Consequence**: `delete_mod` errored on the name check, so the entry could never be removed through the UI.
- **Fix**: Removal drops the manifest entry and only skips deleting the file whose name could not be validated. The remote install path now applies the same URL policy up front so new entries are always removable.
- **Tests**: `delete_mod_removes_manifest_entry_even_when_download_url_fails_policy`.

### Q-23 (Low) Cache read failure blocks the async worker and fails the install
- **Where**: `mc_mod/mod.rs`, `get_file`
- **Trigger**: The cache index points at a file that was deleted externally.
- **Consequence**: The error path ran `block_on` on a tokio mutex from inside a tokio worker, then still propagated the read error instead of downloading.
- **Fix**: Treat an unreadable cached file like a corrupt one: prune the index asynchronously and fall through to a fresh download.
- **Tests**: `get_file_redownloads_when_cached_file_is_missing`.

### Q-24 (Low) Manifest writes are not atomic
- **Where**: `modpacks.rs` (all `modConfigV2.json` and `quadrantSync.json` writes), `mc_mod/mod.rs` `install_local_file`
- **Trigger**: A crash or power loss during a manifest write.
- **Consequence**: A truncated manifest, which the lister then reports as an empty legacy pack.
- **Fix**: New `write_file_atomically` helper (temp file, fsync, rename) used for every manifest and sync metadata write. Concurrent register/delete on a stale snapshot is still possible and is noted under "Not addressed".
- **Tests**: `write_file_atomically_replaces_contents_and_cleans_temp_files`.

### Q-25 (Low) `open_link` hands arbitrary strings to the system opener
- **Where**: `src-tauri/src/other/mod.rs`
- **Trigger**: A renderer call with a local path or non-web scheme. No frontend caller exists today, so this needs a compromised renderer.
- **Consequence**: The system opener could launch local files or programs.
- **Fix**: Accept only `http`, `https`, and `mailto` URLs.
- **Tests**: `open_link_accepts_only_web_and_mail_schemes`.

### Q-26 (Medium) Cloud settings sync never notifies renderer subscribers
- **Where**: `account/quadrant_settings_sync.rs`, `events.rs`, `tauri_adapter.rs`, `quadrant-host/src/lib.rs`
- **Trigger**: Settings sync pulls a new UI scale, locale, or decoration flag from the cloud on a second machine.
- **Consequence**: Only the `set_config_value` command emitted `configChanged`, so the app's `onKeyChange` listeners never fired and the value sat unapplied until restart.
- **Fix**: New `BackendEvent::ConfigChanged(key)` published for every synced key and for `lastSettingsUpdated`; both hosts forward it as `configChanged`.
- **Tests**: `get_quadrant_settings_notifies_each_applied_key`, `event_bridge_forwards_config_changes`.

### Q-27 (Medium) Double-clicking sign-in starts two OAuth callback servers
- **Where**: `src/components/Pages/AccountPage/AccountPage.tsx`
- **Trigger**: Click sign-in twice before the callback server has started.
- **Consequence**: Two servers and two URL listeners, the first cleanup was overwritten and leaked, and the login result depended on which listener finished last.
- **Fix**: A synchronous in-flight guard spanning server startup, with the button disabled meanwhile and the guard released in `finally`.
- **Tests**: `AccountPage.test.tsx` (two cases).

### Q-28 (Low) Header title stays in the previous language
- **Where**: `src/App.tsx`
- **Trigger**: A saved non-English locale on startup, or changing language in settings.
- **Consequence**: `content.title` was translated when the page object was stored, so the header showed the old language until navigation.
- **Fix**: Look the title up from the freshly built `pages` array by name.

### Q-29 (Low) Active page highlight compares stale object identity
- **Where**: `src/App.tsx`, sidebar buttons
- **Trigger**: Any render after the first; `page === p` never matches since `pages` is rebuilt each render.
- **Fix**: Use the already computed `isSelected` flag.

### Q-30 (Low) Modpack view fetches every mod twice and identifies twice
- **Where**: `src/components/shared/Pages/ModpackView.tsx`
- **Trigger**: Open a pack; a mount-only effect and the toggle effect both ran the full fetch. The identify button also ran fingerprinting directly and again via its effect.
- **Fix**: Keep the single toggle effect and let it drive identification.
- **Tests**: `ModpackView.test.tsx` (resolves each mod exactly once).

### Q-31 (Low) Export failures never reach the error snackbar
- **Where**: `src/components/Pages/ApplyPage/Apply.tsx`
- **Trigger**: Export to an unwritable destination. The call was not awaited inside its `try`.
- **Fix**: Await the export.
- **Tests**: `Apply.test.tsx` (surfaces an export failure through the snackbar).

### Q-32 (Low) Modpack search can show results for a superseded query
- **Where**: `Apply.tsx`, `updateModpacks`
- **Trigger**: Type quickly; an older request resolving last replaced the newer list.
- **Fix**: Request counter; only the newest response is applied.
- **Tests**: `Apply.test.tsx` (ignores a slow response for a superseded search query).

### Q-33 (Low) Share page uses a raw string instead of an i18n key
- **Where**: `src/components/Pages/ShareSyncPage/ShareSyncPage.tsx`, locale files
- **Fix**: Added `quadrantSync` to all three locales and used it. Locale key parity is enforced by the existing locale test.

## Not addressed

- **Manifest concurrency**: `register_mod`, `delete_mod`, and `update_modpack` still write from the caller's `existing_modpacks` snapshot without the manifest lock that `install_local_file` takes. A concurrent install and delete can lose the newer entry. Fixing this means re-reading the manifest under the lock in each function and is left as follow-up work.
- **`get_modpacks` Tauri command** still returns an empty list on a top-level `read_dir` failure instead of an error, because callers do not handle rejection. It now logs the cause.
